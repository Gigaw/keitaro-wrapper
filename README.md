# Keitaro wrapper

Обёртка над рекламным трекером [Keitaro](https://keitaro.io/): создаёт кампании по шаблону и редактирует офферы в потоках через черновики.

- **Создаватор.** Форма: название, страна (ISO-код, например `AU`), ID оффера, домен, группа и источник трафика. Списки загружаются из Keitaro. Создаёт в Keitaro кампанию с двумя потоками:
  1. посетители из выбранной страны → редирект на https://google.com;
  2. выбранный оффер с весом 100%.
- **Редактор.** Загружает потоки из Keitaro (Fetch Streams). Позволяет добавлять, удалять и закреплять офферы в черновике с автоматическим пересчётом весов. В Keitaro изменения уходят только по кнопке Push.

Стек: FastAPI, SQLAlchemy 2, Alembic, SQLite, httpx; фронт на React + TypeScript (Vite).

## Требования
- Python 3.11+ (проверено на 3.15)
- Node.js 18, 20 или 22+ (проверено на 22)
- API-ключ Keitaro. Его создают в админке: «Обслуживание» → «Пользователи» → пользователь → «API-ключи».

## Установка и запуск

```bash
# 1. Бэкенд
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 2. Настройки
cp .env.example .env
# впишите KEITARO_API_KEY (и KEITARO_URL, если трекер другой)

# 3. База данных: создаёт app.db и таблицы
alembic upgrade head

# 4. Запуск API на http://localhost:8000 (документация: /docs)
uvicorn app.main:app --reload
```

Фронт запускается в отдельном терминале:

```bash
cd frontend
npm install
npm run dev
```

Откройте http://localhost:5173. Vite перенаправляет запросы `/api` на бэкенд (порт 8000), поэтому бэкенд должен быть запущен.

### Переменные окружения (`.env`)
| Переменная | Пример | Что это |
|---|---|---|
| `KEITARO_URL` | `https://tlgk.host` | адрес трекера, без `/admin_api` |
| `KEITARO_API_KEY` | — | ключ Admin API |
| `DATABASE_URL` | `sqlite:///./app.db` | база SQLAlchemy |

### Миграции
- Применить: `alembic upgrade head`.
- После изменения `app/models.py` создать новую миграцию: `alembic revision --autogenerate -m "описание"`, проверить файл в `alembic/versions/` и применить.

## Как устроено

```
app/
  keitaro.py   клиент Keitaro Admin API
  models.py    таблицы и статусы офферов
  weights.py   расчёт весов (чистая функция)
  service.py   логика создаватора и редактора
  main.py      HTTP-эндпоинты
alembic/       миграции
frontend/src/  Creator.tsx (создаватор), Editor.tsx (редактор), api.ts
```

Фронт тонкий: черновики хранятся в базе на бэкенде, поэтому переживают перезагрузку страницы. Каждый запрос, который меняет поток, возвращает поток целиком, и фронт его перерисовывает.

### Таблицы
- `campaigns` — кампания (`keitaro_id`, название, время синхронизации).
- `streams` — поток. В `raw` лежит JSON потока из Keitaro как есть: фильтры и редиректы не разбираются.
- `stream_offers` — оффер в потоке: `share` (вес в черновике), `published_share` (вес в Keitaro), `pinned`, `published_pinned` (pin на момент Push), `status`.

### Статусы оффера
| Статус | Значение | Как попадает |
|---|---|---|
| `active` | опубликован в Keitaro | Fetch, Push |
| `pending_add` | добавлен в черновике | Add, Bring Back из архива |
| `pending_remove` | удалён в черновике (серый, вес 0%) | Delete |
| `removed` | архив: в Keitaro его нет, запись хранится | Push после Delete, или оффер удалили прямо в Keitaro и сделали Fetch |

Поток подсвечивается жёлтым, если в нём есть `pending_*` или вес отличается от опубликованного. Это поле вычисляется, отдельно не хранится.

- **Cancel** удаляет новые `pending_add` (а возвращённые через Bring Back снова уходят в архив), возвращает `pending_remove` в `active`, восстанавливает опубликованные веса и закрепления (pin хранится только у нас; его состояние на момент Push — в `published_pinned`).
- **Push** сначала заново читает поток из Keitaro. Если там офферы или веса изменились после последнего Fetch, Push отменяется: нужно сделать Cancel, затем Fetch. Иначе в Keitaro отправляется итоговый список офферов (Keitaro заменяет список целиком).
- **Fetch** не трогает потоки с неопубликованными изменениями и выводит предупреждение.

### Веса
- Участвуют офферы `active` и `pending_add`.
- Закреплённые (pin) сохраняют свой вес. Остаток делится поровну между незакреплёнными.
- Keitaro принимает только целые веса, поэтому остаток от деления раздаётся по 1% первым офферам: 100/3 → 34/33/33. Сумма всегда ровно 100.
- Ошибка, если: сумма закреплённых больше 100%; закреплены все, а сумма не 100%; закреплённые заняли 100%, а незакреплённые есть.

## Ограничения
- В редакторе открываются только кампании, созданные через создаватор.
- Если Keitaro не создаст поток, кампания останется в Keitaro без потоков.
- Потоки, удалённые в Keitaro, из нашей базы не удаляются.
